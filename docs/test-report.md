## 三、测试项目详解

### 测试项 1 ｜ 人体存在检测准确率

#### 测试方法

在距设备 1 m、2 m、3 m、4 m、5 m 五个距离上，每个距离进行 20 次「进入 / 离开」试验，共 100 次。每次试验中：

1. 测试人在指定距离外站定，等设备稳定显示「无人」
2. 测试人步入指定距离内，停留 5 秒
3. 观察 OLED 是否在 3 秒内显示「有人 + 运动 / 静止」
4. 测试人离开，观察 OLED 是否在 5 秒内回到「无人」

**正确判定**：OLED 显示状态与实际状态在 5 秒内一致。

#### 测试数据

| 距离 (m) | 试验次数 | 正确次数 | 准确率 |
| ---: | ---: | ---: | ---: |
| 1 | 20 | 20 | 100% |
| 2 | 20 | 20 | 100% |
| 3 | 20 | 19 | 95% |
| 4 | 20 | 19 | 95% |
| 5 | 20 | 18 | 90% |
| **合计** | **100** | **96** | **96%** |

#### 错误分析

- 5 m 处出现 2 次误判，原因：测试人靠近墙边时，雷达受墙面多径反射干扰
- 3 m / 4 m 各 1 次误判，原因：测试人姿势特别静止（屏息）超过 10 s，被识别为「无人 + 微动消失」

#### 优化方向

- 增加 LD2410B 灵敏度档位配置
- 应用层加 5 s "存在防抖"逻辑（连续 5 s 无能量再判离开）

### 测试项 2 ｜ 有效检测距离

#### 测试方法

测试人从 0.5 m 起步缓慢远离设备，每 0.5 m 停留 10 s，记录 OLED 是否稳定显示「有人」。直到设备出现连续误判（连续 3 次显示「无人」）时记录该距离为「失效距离」。

#### 测试数据

| 距离 (m) | 是否稳定检测 |
| ---: | :-: |
| 0.5 | ✅ |
| 1.0 | ✅ |
| 1.5 | ✅ |
| 2.0 | ✅ |
| 2.5 | ✅ |
| 3.0 | ✅ |
| 3.5 | ✅ |
| 4.0 | ✅ |
| 4.5 | ✅ |
| 5.0 | ⚠️ 偶发漏判 |
| 5.5 | ❌ 频繁漏判 |
| 6.0 | ❌ 不可用 |

#### 结论

- **稳定检测距离**：4.0 m
- **可用检测距离**：5.0 m（偶发误差可接受）
- **失效距离**：5.5 m 以上

实际工程结论：**4 – 5 m 范围内稳定可用**，符合家居场景（卧室、客厅）需求。

### 测试项 3 ｜ 呼吸频率估计误差

#### 测试方法

测试人静坐距 LD6002 模组 0.5 m 处，保持自然呼吸。同步用：

1. **基准**：手机秒表，由测试人按胸口起伏手动计数 60 秒
2. **被测**：OLED 显示的呼吸频率读数（经三道过滤后）

各进行 10 组试验，每组记录两个数值。

#### 测试数据

| 组次 | 基准 (bpm) | OLED 显示 (bpm) | 绝对误差 |
| ---: | ---: | ---: | ---: |
| 1 | 16 | 18 | 2 |
| 2 | 14 | 17 | 3 |
| 3 | 18 | 15 | 3 |
| 4 | 15 | 19 | 4 |
| 5 | 17 | 14 | 3 |
| 6 | 16 | 20 | 4 |
| 7 | 14 | 16 | 2 |
| 8 | 18 | 14 | 4 |
| 9 | 15 | 19 | 4 |
| 10 | 16 | 18 | 2 |
| | | **平均** | **3.1** |
| | | **最大** | **4** |

#### 结论

- **平均误差**：3.1 bpm
- **最大误差**：4 bpm
- **结论**：**呼吸频率误差 ≤ ± 4 bpm**

#### 误差来源分析

1. 基准本身不精确（手动计数 ± 1 bpm 系统误差）
2. LD6002 模组输出本身有 ± 2 bpm 的内置抖动
3. 测试人无法完全静止（轻微体动会被识别为呼吸信号）

#### 注意（重要免责声明）

⚠️ **本项目为工程级精度验证，不是医疗级**。任何医疗级呼吸监测都需要专业基准设备（如 Polar H10 心率带、医用呼吸传感器）和大样本量统计。本结果仅证明系统工程可用。

> 📷 **建议截图位置**：手机秒表计数 + OLED 显示同框照片

### 测试项 4 ｜ 端到端云端延迟

#### 测试方法

「端到端延迟」定义为：**从传感器状态改变 → 微信小程序界面刷新** 的总时间。

1. 手机横屏录屏，同时画面里包含：
   - 测试人走入检测区的动作
   - OLED 屏幕显示
   - 另一台手机的微信小程序「巴法云」订阅页面
2. 测试人走入检测区，触发状态变化
3. 录屏结束后逐帧（30 fps，每帧 33 ms）分析：
   - T₀ = 测试人完全进入检测区的帧
   - T₁ = OLED 显示「有人」的帧
   - T₂ = 微信小程序刷新出新状态的帧
4. 计算延迟 = T₂ - T₀，重复 10 次

#### 测试数据

| 组次 | 延迟 (s) | 备注 |
| ---: | ---: | --- |
| 1 | 2.1 | |
| 2 | 1.8 | |
| 3 | 4.5 | Wi-Fi 偶发卡顿 |
| 4 | 2.0 | |
| 5 | 2.3 | |
| 6 | 1.9 | |
| 7 | 2.5 | |
| 8 | 3.8 | |
| 9 | 2.2 | |
| 10 | 2.7 | |
| | **平均 2.58** | **最大 4.5** |

#### 结论

- **平均延迟**：约 2.6 s
- **最坏情况**：4.5 s（仍 < 5 s 目标）
- **结论**：**端到端延迟 < 5 s** ✅

#### 延迟构成分析

```
传感器输出 (100 ms)  ████
       ↓
状态机解析 (10 ms)   ▌
       ↓
ESP8266 AT 发送 (300 ms) ████████████
       ↓
TCP 上行到巴法云 (500 ms) ████████████████████
       ↓
巴法云转发 (200 ms)  ████████
       ↓
小程序订阅 (1000 ms)  ████████████████████████████████████
       ↓
界面刷新 (50 ms)     ██
─────────────────────────────────
总计 ≈ 2.16 s（最佳情况）
```

主要时延花在**云端转发 + 微信小程序订阅刷新**，本地处理只占不到 5%。

### 测试项 5 ｜ 长稳运行测试

#### 测试方法

设备连续上电运行 **72 小时**，全程不重启、不操作。每 12 小时记录：

1. OLED 是否仍正常刷新
2. 微信小程序数据是否正常更新
3. 是否有 MCU 死机 / Wi-Fi 掉线无法恢复 / 数据卡死

#### 测试数据

| 检查点 | OLED | Wi-Fi 状态 | 数据更新 | 是否重启 | 备注 |
| --- | :-: | :-: | :-: | :-: | --- |
| 0 h | ✅ | ✅ | ✅ | — | 启动 |
| 12 h | ✅ | ✅ | ✅ | ❌ | 正常 |
| 24 h | ✅ | ⚠️→✅ | ✅ | ❌ | 出现 1 次 TCP 断连,自动重连成功 |
| 36 h | ✅ | ✅ | ✅ | ❌ | 正常 |
| 48 h | ✅ | ✅ | ✅ | ❌ | 正常 |
| 60 h | ✅ | ⚠️→✅ | ✅ | ❌ | 出现 1 次发布失败,失败计数+1 后自愈 |
| 72 h | ✅ | ✅ | ✅ | ❌ | 正常 |

#### 结论

- **72 小时全程 MCU 零重启** ✅
- **共发生 2 次 TCP 异常事件，自动重连均成功恢复**
- **结论**：长稳运行可靠性达到设计目标

#### 关键设计的贡献

| 设计 | 在长稳测试中的作用 |
| --- | --- |
| 环形缓冲区 | 突发数据不丢字节 |
| 双校验和 | 不会因传输噪声导致脏数据 |
| 失败计数 + 自动重连 | 自愈 TCP 偶发断连 |
| 人体存在防抖 | 避免短暂误判触发频繁上报 |
| 静态分配（无 malloc） | 无内存碎片化风险 |

## 四、综合评价

### 5 项指标全部达标

| 指标 | 设计目标 | 实测 | 余量 |
| --- | --- | --- | --- |
| 准确率 | ≥90% | 96% | +6% |
| 检测距离 | ≥4 m | 5 m | +25% |
| 呼吸误差 | ≤±5 bpm | ±4 bpm | -20% |
| 端到端延迟 | ≤10 s | <5 s | -50% |
| 长稳运行 | ≥24 h | 72 h | +200% |

### 已知不足

1. 久坐识别没有严格量化测试，只做了功能验证（连续静坐 → 触发 / 起身 → 复位）
2. 呼吸误差测试样本量偏小（n=10），统计意义有限
3. 长稳测试场景单一（仅一个 Wi-Fi 环境）
4. 未在极端环境（高温、强电磁干扰）下测试
